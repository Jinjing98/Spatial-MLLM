# debug_only

当用户只希望进行调试分析时使用本技能：定位问题、解释原因、提出方案，但**不改代码**。

## 适用范围

- 复现并分析故障/异常。
- 识别可能根因，并给出代码级证据。
- 提供可执行的修复方案与权衡。
- **不**打补丁、**不**改文件、**不**执行破坏性命令。

## 输出要求（固定结构）

1. **先给发现（按严重度排序）**
2. **证据**（文件路径 + 关键行/函数）
3. **根因假设**（可给多个并排序, but do not have to, if u are certain the root cause）
4. **修复建议**（最小改动优先，说明风险 if there are any.）

## 规则

- 本模式下禁止修改代码。
- 优先基于真实代码与日志给结论。
- 明确写出假设条件。
- 若结论不确定，给出置信度和消歧所需信息。
- 若无法复现，说明已尝试步骤与缺失信息。

## 回答风格

- 简洁、技术化、可执行。
- 先关键结论，再补充细节。
- 尽量附精确文件引用。
